# 手法目录：重新组织数据

> 提炼自《重构（第二版）》第 9 章。括号内数字为原书页码，仅供人工溯源。
> 主题：变量的责任拆分、字段命名、派生数据、引用与值的转换。

## 9.1 拆分变量 Split Variable（240）
曾用名：移除对参数的赋值/分解临时变量。

**动机**：变量多次赋值 = 承担多个责任，令读者糊涂（"一个值用于多个用途是催生混乱和 bug 的温床"）。例外：**循环变量**和**结果收集变量**（累加、拼接、写入流、向集合添加）天然被多次赋值，不要拆。

**做法**：
1. 在声明及第一次赋值处改名，尽量声明为不可修改。
2. 以第二次赋值为界，修改之前所有引用指向新变量。测试。
3. 重复，直到处理完最后一处赋值。
4. 对输入参数赋值的场景：`let result = inputValue;` 分离"输入"与"结果"两个责任，判断条件继续用原始输入（语义更准确）。

## 9.2 字段改名 Rename Field（244）

**动机**：数据结构是理解程序行为的关键（Fred Brooks："给我看表单，不需要流程图就能柳暗花明"）。类的取值/设值函数在用户看来就是字段，改名同样重要。

**做法**：
- 作用域小：直接改所有引用，测试，完成。
- 广泛使用的数据结构（重量级做法）：
  1. 未封装则先封装记录(162)——封装后改名变成四处可分别小步处理：内部字段、构造函数、取值函数、设值函数。
  2. 内部私有字段改名（`_name`→`_title`），调整内部访问。测试。
  3. 构造函数兼容新旧名（`data.title !== undefined ? data.title : data.name`），逐个迁移调用方，最后去掉旧名支持。
  4. 访问函数用函数改名(124)换新名。
- 不可变数据结构：复制旧字段到新名下，逐一改使用方，删旧字段（可变数据这样做会招致灾难，不可变则没有麻烦）。
- 测试被破坏 = 信号：改用更渐进的方式。

## 9.3 以查询取代派生变量 Replace Derived Variable with Query（248）

**动机**：可随时计算出来的派生变量应该去掉——计算更清晰，且杜绝"源数据修改时忘了更新派生变量"。**例外**：源数据不可变且结果也可强制不可变时，"变换生成新结构"的风格可以保留（对象风格 vs 函数风格之别；源数据会被修改→对象风格更好）。

**做法**：
1. 识别所有更新点，必要先用拆分变量(240)分割（如初始值与累加值分离：`_initialProduction` + `_productionAccumulator`）。
2. 新建函数计算该变量的值。
3. 引入断言(302)：变量值 === 计算值（谨慎验证猜想，不止一个数据来源时尤其必要）。必要时用封装变量(132)包住断言。测试。
4. 读取处改调计算函数。测试。
5. 移除死代码(237)删掉变量的声明与赋值。

## 9.4 将引用对象改为值对象 Change Reference to Value（252）
反向：将值对象改为引用对象(256)。

**动机**：值对象不可变，更易理解、可放心复制传递，分布式/并发系统尤佳。**何时不做**：需要多个对象共享并同步看到修改的，应保持引用。

**做法**：
1. 检查目标是否为不可变（或可改为不可变）。
2. 用移除设值函数(331)逐一去掉设值函数（调用者改为整体替换对象：`this._telephoneNumber = new TelephoneNumber(arg, this.officeNumber)`）。
3. 提供基于值的相等性判断（覆写 equals/==，通常同时覆写 hashCode/散列码），用字段值比较。为相等性写测试（含不相等、与 null/异类比较）。

## 9.5 将值对象改为引用对象 Change Value to Reference（256）
反向：将引用对象改为值对象(252)。

**动机**：多份数据副本代表同一逻辑实体（同一顾客的多张订单）。数据不修改则两种皆可；**需要更新共享数据时，必须找齐所有副本同步更新，漏一处即不一致**——此时改为单一引用，修改立即反映到所有关联处。代价：需要一个仓库（repository）保证"一个实体只有一个代表对象"。

**做法**：
1. 为相关对象创建仓库（若还没有）：按 ID 注册/查找，每个 ID 只创建一次对象（`registerCustomer(id)` + `findCustomer(id)`）。
2. 确保构造函数能找到正确实例（如输入数据含 ID）。
3. 宿主对象构造函数改为从仓库获取关联对象，每次修改测试。

注意：构造函数与全局仓库的耦合须小心对待（"全局对象像强力的药物"）；可将仓库作为参数传入。
