# 代码健康度评分（5 分制）

> 把坏味道诊断压缩成一个用户一眼能懂的分数，如实告知扫描范围内的代码健康状况。
> 分数不是独立审计，而是诊断证据的汇总：先按 `smells.md` 诊断，再按本规则打分。
> 判断原则沿用原书：**没有任何量化标准比得上见识广博者的直觉**——分数是沟通工具，不是 KPI。

## 计分规则

满分 **5 分**，总分保留一位小数。6 个维度覆盖全部 24 种坏味道，**等权平均**（按"这一面健康与否"计，不按坏味道条数加权）：

| 维度 | 覆盖的坏味道（smells.md 编号） |
|------|------|
| D1 命名与可读性 | 1 神秘命名；24 注释（除臭剂式） |
| D2 函数与逻辑 | 3 过长函数；4 过长参数列表；12 重复的 switch；13 循环语句 |
| D3 数据组织 | 5 全局数据；6 可变数据；10 数据泥团；11 基本类型偏执；16 临时字段；22 纯数据类 |
| D4 模块与边界 | 7 发散式变化；8 霰弹式修改；9 依恋情结；17 过长消息链；18 中间人；19 内幕交易；20 过大的类；21 异曲同工的类 |
| D5 抽象与继承 | 14 冗赘元素；15 夸夸其谈通用性；23 被拒绝的遗赠 |
| D6 重复 | 2 重复代码 |

**单维度锚点**（每维度打整数分）：

| 分 | 该维度状况 |
|----|-----------|
| 5 | 未发现该类坏味道 |
| 4 | 个别轻微：1~2 处，影响局部，顺手可修 |
| 3 | 明确存在：多处轻微，或 1 处明显，值得列入重构方案 |
| 2 | 广泛存在，或已到结构级（要拆类/搬移/多态化才能解决） |
| 1 | 系统性蔓延：改任何相关功能都疼，动手前先补测试 |

**总分** = 已评维度的算术平均，四舍五入到一位小数。

- **未评维度**：样本不足以判断的维度（如增量扫描判断不了霰弹式修改）标"未评"，从平均中剔除并注明原因；可评维度不足 2 个时不出总分，只给定性结论。
- **短板警示**：任一维度 ≤ 2 时，在结论后追加一句警示（如"其中数据组织 2 分，已属结构级问题"），不许让平均分掩盖最疼处。
- 分数来自坏味道证据的判断，不是行数、圈复杂度等指标的机械换算；linter 输出可作线索，定分仍凭证据。

## 等级带

| 总分 | 结论 | 建议动作 |
|------|------|----------|
| 4.5 ~ 5.0 | 健康 | 无须专项重构，保持营地法则 |
| 3.5 ~ 4.4 | 尚可 | 适合捡垃圾式清理：路过顺手修个别坏味道 |
| 2.5 ~ 3.4 | 有债 | 建议针对性重构，从最疼的一处开始 |
| 1.5 ~ 2.4 | 重债 | 先补测试安全网，再分批规划重构 |
| 1.0 ~ 1.4 | 危险 | 认真评估"重写 vs 重构" |

## 评分卡格式

诊断完成后输出评分卡（并入第 4 步方案的开头）：

```text
## 代码健康度：<范围描述> —— 3.6 / 5（有债）

| 维度 | 得分 | 依据（文件/函数 · 坏味道） |
|------|------|----------------------------|
| 命名与可读性 | 4 | src/order.ts:42 神秘命名：processData() |
| … | | |

- 未评维度：模块与边界（增量样本不足，无法判断霰弹式修改）
- 最疼的三处：① … ② … ③ …（即重构方案的优先序）
- 测试安全网：有 / 无——不计入分数，但决定这些债敢不敢马上还
```

## 评分模式（用户只要分数，不动手）

**评分只伴随全仓库扫描给出**：默认增量模式只诊断、不打分——增量样本太薄，撑不起六个维度的判断。用户要求"打个分 / 评估一下代码质量"时，征得其同意做全仓库扫描（应分模块进行，避免一次铺开过大），输出评分卡后**停在决策关口**——把"最疼的三处"作为可选重构方向报给用户，等其决定是否进入方案与执行。全程只读不动。

## 诚实性条款

1. **证据先于分数**：每个维度分都必须落到具体文件/函数与坏味道名上；给不出证据的维度按"未评"处理，不许凭整体印象打分。
2. **分数描述的是扫描范围**：增量扫描的分数只代表增量改动，不代表全仓库；评分卡必须写清范围。
3. **分数不绕过关口**：分数再低也不自动动手，第 4 步"未获批准不动一行"照常生效。
4. **分数不是判决**：低分不等于"烂仓库"——坏味道是迹象不是判决；同一段代码两次诊断相差 ±0.3 属正常波动，不追求复现到小数点后。
5. **收尾要重评**：重构完成后对动过的范围重新打分，向用户汇报前后对比（如 3.6 → 4.2）。
